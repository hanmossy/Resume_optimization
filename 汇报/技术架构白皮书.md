## 一、总体架构

单层本地 Web 应用，无数据库、无登录、无网络爬取。全部状态存在于 Streamlit `st.session_state`，会话结束即销毁（天然满足隐私与合规）。

```
简历辅导/
├── main.py              # Streamlit 界面与流程编排（唯一直接依赖 st 的文件）
├── config.py            # 全部配置：API、模型名、路径、评分权重（禁硬编码于他处）
├── llm_client.py        # LLM 调用封装：DeepSeek 主用 + 备用热切换 + 缓存模式
├── job_analyzer.py      # 岗位 JD 解析 → 结构化能力项清单
├── resume_parser.py     # 简历 PDF/TXT → 结构化字典
├── gap_matcher.py       # 双通道 Gap 诊断：LLM 语义判断 + 规则评分
├── rewriter.py          # 逐条 Gap 的诊断 + 建议 + 改写示例
├── pdf_exporter.py      # 全流程数据 → 诊断报告 PDF
├── data/
│   ├── jobs/            # 预设岗位库（16 个 JSON，人工核验）
│   ├── prompts/         # 全部 Prompt 模板（与代码分离，便于审查与调优）
│   └── cache/           # 演示缓存（3 个 Demo 案例全流程输出）
├── requirements.txt
└── .env.example         # API 密钥模板（真实 .env 不进 Git）
```

**为何比任务书多一个 `llm_client.py`**：任务书列了 7 个文件，但"DeepSeek 主用 + 备用切换 + 缓存降级"是横切关注点，若散落在各业务模块会导致 DeepSeek 审查时需在 5 个文件里重复验证同一段重试逻辑。集中为单一客户端模块，业务模块只面向 `llm_client.chat()` 一个接口编程。此为对任务书模块清单的唯一变更，特此说明。

## 二、模块接口契约

约定：跨模块传递的数据一律为 **TypedDict**（定义于各产出模块顶部，DeepSeek 可静态检查），禁止传递裸 dict。

### 2.1 config.py（无函数，纯配置）

```python
# 关键配置项（值从环境变量读取，提供安全的默认值）
DEEPSEEK_API_KEY: str      # 来自环境变量 DEEPSEEK_API_KEY，缺失时进入缓存模式
DEEPSEEK_BASE_URL: str = "https://api.deepseek.com"
PRIMARY_MODEL: str = "deepseek-chat"
FALLBACK_MODEL: str = ""   # 备用模型（Moonshot），留空表示不启用
DEMO_CACHE_MODE: bool      # True 时全部 LLM 调用读缓存，断网可演示
JOBS_DIR / PROMPTS_DIR / CACHE_DIR: Path
MATCH_WEIGHTS: dict        # 评分权重，见 2.5
PDF_FONT_PATH: str         # 中文字体路径（宋体），防中文乱码
```

### 2.2 llm_client.py

```
chat(prompt_key: str, user_content: str, expect_json: bool = True) -> dict
```
- 职责：读 Prompt 模板 → 调 DeepSeek（OpenAI 兼容协议）→ JSON 解析与校验 → 失败重试 1 次 → 降级备用模型 → 缓存模式短路。
- 异常契约：所有失败最终抛 `LLMUnavailableError`，业务模块捕获后向界面返回友好提示，**绝不静默吞异常**。
- 缓存键：`sha256(prompt模板版本 + 输入)`，命中即返回，演示稳定性兜底。

### 2.3 job_analyzer.py

```
load_preset_jobs() -> list[JobMeta]                # 岗位库目录列表（供选岗下拉框）
analyze_job(job_id: str | None, jd_text: str | None) -> JobRequirements
```
- 输入二选一：预设岗位 ID（读本地 JSON）或用户粘贴的 JD 原文（走 LLM 抽取）。
- `JobRequirements` 结构：
```python
class AbilityItem(TypedDict):
    name: str            # 能力项名，如"SQL 数据分析"
    category: str        # 硬技能 / 软技能 / 背景门槛
    importance: int      # 1-5，岗位方重要度（LLM 评估 + 人工抽检）
    evidence: str        # JD 原文依据（引文，供界面展示与人工核验）
class JobRequirements(TypedDict):
    job_title: str
    company_type: str    # 金融/互联网/四大/快消/咨询
    responsibilities: list[str]
    abilities: list[AbilityItem]   # 8-12 项，Gap 对比的原子单位
    salary_hint: str     # 可空；预设库中人工填写，LLM 不得编造
```

### 2.4 resume_parser.py

```
parse_resume(file_bytes: bytes, filename: str) -> ResumeData
```
- PDF 走 `pypdf` 文本层提取；扫描件 PDF（无文本层）显式抛 `ScannedResumeError` 并提示用户转 TXT——**不做 OCR**（范围守卫：OCR 是排期黑洞）。
- 提取文本 → LLM 结构化为：
```python
class ResumeData(TypedDict):
    education: list[str]     # 学校/专业/年级（展示时脱敏学校名，防 -15 分红线）
    internships: list[str]   # 每段实习的原文条目
    projects: list[str]
    skills: list[str]
    raw_text: str            # 原文，供改写模块引用
```

### 2.5 gap_matcher.py（双通道核心）

```
diagnose(job: JobRequirements, resume: ResumeData) -> GapReport
```
- **LLM 通道**：对每个 `AbilityItem` 判断 resume 侧为 `matched / partial / missing`，并输出 `reason`（引用简历原文证据）。LLM **只输出判断与依据，不输出分数**。
- **规则通道**（确定性评分，写死公式，可复现）：
```
单能力项得分 = importance × {matched:1.0, partial:0.5, missing:0.0}
匹配度 = Σ单项得分 / Σimportance × 100，保留整数
```
- `GapReport`：
```python
class GapItem(TypedDict):
    ability: str
    status: Literal["matched", "partial", "missing"]  # 驱动绿/黄/红三色标注
    importance: int
    reason: str            # LLM 依据（含简历引文）
class GapReport(TypedDict):
    match_score: int       # 0-100，规则通道产出
    items: list[GapItem]   # 与岗位能力项一一对应
    top_gaps: list[str]    # 按 importance×缺失度 排序的 Top3，供改写模块聚焦
```

### 2.6 rewriter.py

```
rewrite(gap: GapItem, resume: ResumeData, job: JobRequirements) -> RewriteResult
# RewriteResult = {diagnosis, suggestion, example_before, example_after}
```
- 仅对 `top_gaps`（≤3 条）逐条调用，保证"一次点击出完整报告"（异议三约束）。
- Prompt 硬约束：改写示例**只能重组简历已有事实，禁止虚构经历**——对应扣分项②防线，Prompt 模板中显式声明，DeepSeek 可直接审查该约束文本。

### 2.7 pdf_exporter.py

```
export_pdf(job, resume, report, rewrites, out_path: Path) -> Path
```
- `reportlab` 生成，内嵌宋体（config 指定字体路径，解决中文乱码）；内容为诊断报告（岗位画像 / 匹配度 / Gap 清单 / 改写建议），**不是重新排版简历**（范围守卫：简历排版是模板市场逻辑，不做）。
- 报告中自动附"AI 使用声明与人工核验说明"页脚——直接服务评分标准"制作 10 分"中的"AI 使用声明完整"。

### 2.8 main.py（Streamlit 编排，4 个页面区块）

1. **选岗区**：下拉框（预设库）或粘贴 JD →「分析岗位」按钮；
2. **岗位画像区**：能力项清单左栏展示（含 JD 依据引文）；
3. **上传诊断区**：传简历 + 背景信息 →「开始诊断」→ 右侧对照视图（能力项 vs 命中状态三色标注）+ `st.metric` 匹配度仪表；
4. **改写导出区**：Top3 Gap 的诊断/建议/前后对照 →「导出 PDF」。

交互计数：「分析岗位」1 次点击 +「开始诊断」1 次点击 = **2 次点击出完整报告**，满足异议三。

## 三、数据流图（文字版）

```
用户选岗/粘贴JD
  → main.py 调 job_analyzer.analyze_job()
      → 预设路径：读 data/jobs/*.json（零 LLM 调用，秒回）
      → 自定义路径：llm_client.chat("job_extract") → DeepSeek → JSON 校验
  → 界面渲染 JobRequirements（左栏能力项清单）
用户上传简历PDF/TXT + 背景
  → main.py 调 resume_parser.parse_resume()
      → pypdf 提取文本（扫描件 → 显式报错引导转TXT）
      → llm_client.chat("resume_extract") → ResumeData
  → main.py 调 gap_matcher.diagnose(job, resume)
      → LLM 通道逐能力项判断 status+reason（批量一次调用，非逐条，省时长）
      → 规则通道按固定公式算 match_score
  → 界面渲染对照视图 + 匹配度 + 三色标注
用户点「生成改写建议」（或并入诊断一步完成）
  → rewriter.rewrite() × Top3 Gap → RewriteResult
用户点「导出 PDF」
  → pdf_exporter.export_pdf(全流程数据) → 本地文件 + 界面下载按钮
演示兜底：config.DEMO_CACHE_MODE=True 时，llm_client 全部命中
  data/cache/ 预落盘 JSON，链路形态不变，仅 LLM 调用替换为读盘
```

## 四、模型接入策略

| 层级 | 方案 | 触发条件 |
|---|---|---|
| 主用 | DeepSeek API（`deepseek-chat`，OpenAI 兼容协议，`response_format=json_object`） | 默认 |
| 备用 | Moonshot API 热切换 | DeepSeek 连续 2 次超时/5xx，config 一行启用 |
| 兜底 | 演示缓存模式 | 无 Key / 拍摄现场断网，3 个 Demo 案例全流程可跑 |

- 超时 30s、重试 1 次、指数退避；密钥仅从环境变量读取；`.env` 入 `.gitignore`。
- 全部 Prompt 存 `data/prompts/*.txt`，含版本号注释（缓存键含版本号，改 Prompt 自动失效旧缓存）。

## 五、预设岗位库（16 个，演示零爬取）

金融 4：券商行研实习、银行管培、基金运营、风控助理；
互联网 4：产品助理、数据分析、后端开发、运营；
四大 2：审计、税务；
快消 2：市场管培、供应链；
咨询 2：管理咨询实习、商业分析；
泛用 2：人力资源、新媒体运营。

每个 JSON 含 `job_title / company_type / responsibilities / abilities / salary_hint / source_note`（来源说明，人工核验记录）——JD 由团队人工整理自公开招聘描述并核验，**禁止让 AI 生成 JD 充当真实岗位**（扣分项②防线）。

## 六、可审查性承诺（给 DeepSeek 的审查地图）

1. 核心算法（评分公式、Gap 状态机）为纯函数，集中在 `gap_matcher.py`，约 80 行，可独立单测；
2. 每个模块顶部：模块说明 + 依赖清单 + 接口契约注释；
3. 每个函数：Google Style Docstring（功能/参数/返回/异常）；
4. 全流程类型注解；跨模块数据结构为 TypedDict；
5. 配置、Prompt、密钥、数据四者全部与逻辑分离；
6. 唯一框架耦合点是 `main.py`，业务模块可脱离 Streamlit 独立运行测试。
