## 一、产品形态建议：**Web 方案（Streamlit）**

明确推荐 **Streamlit**，否决 PyQt，理由如下：

1. **演示匹配度**：视频采用"电脑录屏 + 情景演绎"，浏览器界面录屏效果天然优于桌面软件，且评委对"网站"形态认知成本最低（会议记录已定为"做成一个网站"）。
2. **开发速度**：Streamlit 单文件即可渲染交互界面，48 小时-MVP 场景下比 PyQt 节省约 60% 界面开发时间；团队无需学习 Qt 信号槽机制。
3. **零部署风险**：`streamlit run main.py` 本地起服务即可演示，不依赖公网部署、域名、备案，拍摄现场断外网也能跑（配合离线降级，见异议五）。
4. **Gradio 对比**：Gradio 更适合模型 Demo 但页面布局自由度低，难以呈现"Gap 高亮对比"这类定制视图；Streamlit 的 columns/expander/metric 组件足够且更可控。
5. **可审查性**：Streamlit 的"脚本自上而下执行"模型对 DeepSeek 代码审查最友好，业务逻辑与界面逻辑可清晰分离。

## 二、范围冻结确认

**主线流程（复述确认）**：
选岗（预设岗位库）→ AI 分析岗位要求（职责/能力项结构化）→ 用户上传简历（PDF/TXT）+ 填写背景（年级/专业/目标）→ AI 对比并输出 Gap 清单与匹配度 → 给出修改建议与改写示例 → 导出 PDF。

**核心原则（复述确认）**："先分析、再润色"——先解构岗位需求侧，再对照简历供给侧，交互式提醒 + 建议改法，而非一键润色黑盒。

**已明确砍掉（冻结清单，开发期间任何人提出恢复即触发范围守卫拒绝）**：
- ❌ 秋招信息提醒 / 招聘信息聚合
- ❌ 面试辅导 / 面试模拟
- ❌ 实时岗位爬取（演示依赖外网爬取 = 自杀式设计）
- ❌ 用户登录/账号系统、数据库持久化
- ❌ "找公司→投递→面试→实习回写"全流程一体化
- ❌ 移动端适配、多语言、简历模板市场等一切美化型附加项

## 三、战略异议（必须团队裁决的事项）

### 异议一（最高优先级 ⚠️）：第四步交付物规格与评分标准硬性冲突

任务书第四步要求输出"正文 12—15 页的《AI产品说明书》"，但评分标准明确规定**案例文字说明控制在 1000 字以内**。12—15 页的文档无法作为提交物，若按 12—15 页制作并提交，直接不合规。

**我的裁决建议（双文档制）**：
1. **提交版**：《案例文字说明》≤1000 字，严格按官方四段结构（问题场景→协同过程→结果验证→总结反思）+ 官方排版规范（黑体三号标题/宋体四号正文/1.5 倍行距），这是唯一提交 PDF；
2. **内部版**：《技术白皮书 + 产品说明书》不限篇幅，用于：DeepSeek 审查配套、视频脚本素材库、GitHub 作品集、以及说明书分工中"论文/可视化成果"同学的写作底稿。

任务书中的"评分标准对照表"思路保留，但应放在内部版；1000 字提交版没有空间放对照表。**请团队确认采用双文档制，或提出其他方案。**

### 异议二：Gap 对比算法可行性 —— 可行，但必须"双通道"设计

纯 LLM 打分不可控（同一简历两次评分可能漂移，演示翻车风险高）。架构上将采用：
- **LLM 通道**：负责非结构化理解（JD 能力项抽取、简历语义匹配、建议生成）；
- **规则通道**：负责确定性评分（能力项逐条命中/部分命中/缺失三档计数 → 加权出匹配度百分比），评分公式写死在代码里，LLM 只输出判断依据不输出最终分数。

这样匹配度数字可复现、可解释，DeepSeek 审查时能逐行验证。**无此设计则异议成立；采用双通道则此异议解除。**

### 异议三：4 分钟视频讲得完，但交互轮次必须压到 2 轮以内

主链 5 步录屏约 90—120 秒可完成，加上情景演绎开头结尾，总量可控。风险点在"交互式提醒"：若设计成多轮对话式反复修改，视频会变成聊天录屏，评委看不到产品结构。**建议产品交互设计为"一次诊断出完整 Gap 报告 + 每条 Gap 一键看改写示例"，最多 2 次点击完成核心体验。** 此条作为产品设计约束冻结，视频脚本团队请按此上限设计。

### 异议四："先分析再润色"必须可视化，否则评委 30 秒内感知不到差异

纯文本输出的 Gap 分析与"ChatGPT 对话"在评委眼中无差别。必须在界面上提供：**岗位能力项清单（左）↔ 简历命中情况（右）的对照视图 + 匹配度仪表 + Gap 条目红/黄/绿三色标注**。这是创新 20 分与内容 30 分的主要拿分载体，优先级高于一切美化工作。

### 异议五：模型 API 稳定性 —— 三级降级策略

- **主用**：国内直连 LLM API（Moonshot / DeepSeek / 通义千问，决赛环境务必国内服务，排除 OpenAI 等需代理的服务）；
- **备用**：第二家 API 热切换（config.py 中一行切换）；
- **兜底**：**演示缓存模式**——3 个 Demo 案例的全流程模型输出预先落盘为 JSON，拍摄现场若 API 故障，界面从缓存渲染，录屏不受任何影响。API 密钥走环境变量 + config 模板，绝不硬编码（密钥进 GitHub 作品集 = 安全事故）。

### 异议六：扣分项防御（直接影响分数，非技术问题但顾问必须提示）

1. **-15 分红线**：PDF 与视频中不得出现学校名、教师名、学生姓名、团队名称。注意：录屏时电脑用户名、浏览器书签栏、代码编辑器路径都可能泄露身份信息，拍摄前需专项检查；
2. **-5~20 分线**：预设岗位库 15—20 个 JD 必须人工核验来源与准确性（标注信息来源），产品说明书中需写明"AI 输出经人工核验"的验证方式——这恰好也是评分标准"内容 30 分"中明确要求的得分点，防御与得分合一。

### 异议七：DeepSeek 审查友好性 —— 已纳入代码规范

模块单一职责、核心逻辑纯函数化（输入输出不依赖全局状态）、配置与逻辑分离、Google Style Docstring + 完整类型注解。任务书规定的六条代码规范全部采纳，不再赘述。
